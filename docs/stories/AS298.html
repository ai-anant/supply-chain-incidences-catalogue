AS298 · 2022-04

Stolen Heroku and Travis CI OAuth tokens cloned private GitHub repos

CI/CD SaaSTravis CIGit / GitHubnpm

On 12 April 2022 GitHub Security found unauthorized access to npm production
infrastructure using a compromised AWS API key. GitHub's 15 April advisory
says that key came from private npm repositories downloaded with a stolen
OAuth token issued to Heroku or Travis CI, not from a compromise of GitHub's
own token store. The attacker authenticated to the GitHub API with those
OAuth tokens, listed organizations, then selectively listed and cloned
private repositories. GitHub assessed the attacker did not modify npm
packages. Affected OAuth apps were Heroku Dashboard (several IDs) and
Travis CI (ID 9216). Travis CI's 17 April bulletin says a Heroku OAuth key
was stolen and that the key did not grant access to Travis customer
repositories; they revoked integrator tokens anyway. Heroku tracked the
same window as incident 2413.

Mapped techniques

  • T0112 Compromised token
  • T0168 Exfiltration to code repositories
  • T0200 Proprietary data stolen

supply-chain Heroku and Travis CI OAuth apps

T0112 · Initial Access · Compromised token

The tokens in use were OAuth user tokens issued to the Heroku and
Travis CI integrator apps, not GitHub-stored PATs.

post-supply-chain Private repositories and npm AWS

T0168 · Exfiltration · Exfiltration to code repositories

The attacker listed and cloned private repositories the stolen
OAuth tokens could see.

T0200 · Impact · Proprietary data stolen

Downloaded private npm repositories yielded an AWS API key that
was then used against npm production infrastructure. GitHub found
no evidence packages were modified.

Framework gaps noted

  • Travis CI's bulletin and GitHub's advisory disagree on whether Travis customer repositories were reachable with the stolen Heroku key. The mapped behavior is the GitHub-observed clone and the npm AWS key, not a Travis build takeover.
