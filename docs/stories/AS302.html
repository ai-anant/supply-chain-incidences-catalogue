AS302 · 2026-10

tensorlake 0.5.144 steals tokens, then wipes the home directory if they are revoked

npmGit / GitHubGitHub ActionsDeveloper workstationAI coding agentsVS Code / IDELinux distro / packagesWindows software

On 8 October 2026 StepSecurity reported tensorlake@0.5.144 on npm.
The registry still listed that version as latest at collection, published
01:12 UTC, with a preinstall of node lib/setup.mjs. Version 0.5.143 was
published 6 October and is the pin StepSecurity recommends.

The payload files were committed to main of tensorlakeai/tensorlake.
StepSecurity names the range e90c47b to 6386121 and says the first
commit landed at 01:20 UTC on 7 October, with seven more over the
following hours, none through a pull request. GitHub shows 13 commits
in that range, all authored as Shanshan Wang (login cooleel). The first,
"Add files via upload", was committed through the web UI (committer
web-flow). The last is 23:41 UTC the same day. Neither the blog nor
the commits establish that the named person was the operator.

At 00:08 UTC on 8 October, cooleel started a workflow_dispatch of
"Release - TypeScript SDK (npm)" on 6386121 (Actions run 37706134202).
It succeeded. npm recorded the 0.5.144 publish at 01:12 UTC, matching
StepSecurity. The package carries a provenance attestation because it
was built from that repo's main. The attestation names the build. It
does not say the commit was safe.

setup.mjs skips CI, so developer machines are the target. It downloads
the Bun runtime and runs an obfuscated 856 KB file, which StepSecurity
decoded without executing. The payload collects GitHub and npm tokens,
cloud keys, Kubernetes and Vault secrets, SSH keys, saved browser
logins, and config for Claude, Cursor, and Windsurf. It encrypts that
data and sends it to a public GitHub repo it creates in the victim's
account, or to iseekaigogo.com. The repo description the payload sets
is attacker branding. It is not evidence this is the 2025 Shai-Hulud
wave or a later named wave.

With a stolen npm token it downloads the victim's packages, adds
itself, bumps the version, and republishes them. With a stolen GitHub
token it commits .claude/settings.json (a SessionStart hook) and
.vscode/tasks.json (a folderOpen task) into repos it can write, as
claude@users.noreply.github.com, message "chore: update dependencies".

If it has a GitHub token it also installs gh-token-monitor. For up to
24 hours the service checks that token against the GitHub API every
60 seconds. If GitHub rejects it, the service runs rm -rf ~/ on Linux
or macOS, or a PowerShell delete of the user profile on Windows.
Revoking the token is what starts the wipe. StepSecurity told
maintainers in tensorlakeai/tensorlake issue 1014. No OSV or GHSA
record existed at collection, and the report names no downstream victim.

Framework gaps noted

  • The commits and the workflow_dispatch use login cooleel. The write-up does not establish compromise versus an authorized maintainer, so this is not mapped as T0113.
  • npm provenance on 0.5.144 is a real attestation of the poisoned main build. That is not T0206, which is forging or omitting provenance.
  • Exfiltration to a public repo created in the victim account, or to iseekaigogo.com, is not T0156 (webhooks).
  • The CI skip and the Bun download have no separate technique.
  • The description the payload writes on its exfil repo is branding. It is not a basis for merging this publish into an earlier wave.
  • No confirmed downstream install is in the report. No GHSA or OSV id existed at collection.
