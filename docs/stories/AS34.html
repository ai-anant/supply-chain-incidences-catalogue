AS34 · 2026-09

GHAPPIER loader via @dforge-core/dforge-mcp trusted publishing

npmMCP

CloudSEK documented a 105-minute window on 9 September 2026 in which
someone with push access to the maintainer account of the legitimate npm
package @dforge-core/dforge-mcp added a remote-code loader, changed three
lines so any push to main started the release workflow, rewrote that
workflow 14 minutes later to publish unattended, and shipped 0.2.21.
The release sat as npm latest for 35 minutes 38 seconds before the
maintainer published a clean 0.2.22. The malicious version carried valid
npm provenance: GitHub Actions OIDC trusted publishing, with the
attacker's commit still in Sigstore. Provenance attested where the
artefact was built, not that the source was honest. The payload is one
line in a 99 KB working JS file (indexe.cjs); later stages delete
themselves from disk. CloudSEK tied a second payload family in another
victim repo to PolinRider (EtherHiding / NullReceiver). No OSV or GHSA
advisory was published. How the maintainer push access was obtained is
not established.

Version 0.2.21 of a real package, not a typosquat.

Provenance was valid and named the attacker's commit. Presence of
trusted-publishing attestation did not mean the commit was authorized.
